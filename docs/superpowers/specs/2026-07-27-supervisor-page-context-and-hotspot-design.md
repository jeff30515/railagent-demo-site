# 主管頁面標題說明與站點熱點設計

## 目標

修正主管工作區兩個資訊層級問題：

1. 首頁恢復原本 React 提供的「站點熱點」長條表。
2. 首頁與歷史頁都使用清楚的頁面標題與一行說明文字。

## 首頁

頁面內容依序為：

1. 主標題「即時營運監控」。
2. 說明文字「掌握拾獲物品、旅客追蹤與各站點即時營運概況」。
3. 現有即時 KPI：拾獲物品、旅客追蹤。
4. 現有站務人力：板橋站務、桃園青埔站務。
5. 原本 React 的「站點熱點」長條表。

「站點熱點」必須恢復原本節點與資料，不另外建立重複表格。既有的「時段熱點」、狀態佇列、優先佇列與待辦 drill-down 仍保持隱藏。

## 歷史頁

頁面內容依序為：

1. 主標題「歷史服務品質分析」。
2. 說明文字「透過事件趨勢、使用次數與服務回饋檢視營運品質」。
3. 既有四個統計區塊：
   - 本月事件量趨勢。
   - RailAgent 使用次數統計。
   - 服務設施回報次數。
   - 服務回饋統計。

歷史頁不得混入即時 KPI、站務人力、站點熱點、原主管待辦或友善轉乘內容。

## DOM 與狀態管理

- 標題與說明由 enhancer 管理，重複執行時沿用既有節點，不重複插入。
- 「站點熱點」保留 React 節點 ownership，只在首頁恢復顯示；切到歷史或帳戶時隱藏。
- 切回首頁時再次顯示同一個「站點熱點」節點。
- 底部導覽固定為「首頁／歷史／帳戶」，圖示節點不得被改寫或移除。

## 驗收條件

1. 首頁顯示精確標題與說明文字。
2. 首頁站務人力下方顯示「站點熱點」長條表。
3. 首頁不顯示「時段熱點」、狀態佇列、優先佇列或待辦 drill-down。
4. 歷史頁顯示精確標題與說明文字。
5. 歷史頁仍只有四個統計區塊。
6. 首頁、歷史、帳戶重複切換後，標題、說明、站點熱點與底部圖示都不重複或遺失。
7. 390px 手機寬度不產生水平溢出。
