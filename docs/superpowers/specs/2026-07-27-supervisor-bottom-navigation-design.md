# 主管底部導覽重整設計

## 目標

將主管工作區由「首頁內上方雙分頁 + 底部待辦頁」改為三個清楚且互相獨立的底部頁面：

1. 首頁：即時營運監控。
2. 歷史：歷史服務品質分析。
3. 帳戶：維持現況。

主管不再需要上方的「即時營運監控／歷史服務品質分析」切換按鈕，也不再顯示原本的待辦頁面。

## 導覽結構

### 首頁

- 底部導覽名稱維持「首頁」。
- 移除頁面上方的「跨運具服務事件中樞」標題。
- 頁面主標題改為「即時營運監控」。
- 移除上方「即時營運監控／歷史服務品質分析」兩個切換按鈕。
- 保留目前已核准的即時營運內容：
  - 拾獲物品總數。
  - 旅客追蹤數量。
  - 板橋站務與桃園青埔站務人力。
- 不恢復已移除的狀態佇列、時段熱點、優先佇列、待辦 drill-down 或 Demo KPI。

### 歷史

- 底部導覽原本的「待辦」改名為「歷史」。
- 點擊後完全取代原本的主管待辦頁面。
- 顯示目前已核准的四個歷史服務品質分析區塊：
  1. 本月事件量趨勢。
  2. RailAgent 使用次數統計。
  3. 服務設施回報次數。
  4. 服務回饋統計。
- 沿用既有的 2023 年 7 月遺失物月曆、RailAgent／設施統計與滿意度資料。
- 不顯示即時 KPI、站務人力、原待辦資料、舊 Demo 卡片或舊主管說明區塊。

### 帳戶

- 底部導覽名稱與頁面行為維持「帳戶」。
- 不修改主管帳戶內容。

## 實作邊界

- 沿用 `assets/supervisor-dashboard-enhancer.js` 與現有歷史分析模組，不直接修改大型 React 編譯檔。
- 現有 React 節點只允許隱藏與恢復，不刪除、不取代，確保原生事件處理仍可運作。
- enhancer 依底部導覽目前的作用中按鈕判斷頁面：
  - 首頁作用中時，建立或顯示即時營運內容。
  - 原待辦作用中時，隱藏原待辦內容並建立或顯示歷史四卡。
  - 帳戶作用中時，不介入頁面內容。
- 上方雙分頁在首頁與歷史頁皆保持隱藏。
- 歷史資料載入失敗時，仍顯示四個區塊、數字 `—` 與「統計資料暫時無法讀取」。

## 狀態與資料流

- 即時營運監控繼續讀取現有拾獲物品與旅客追蹤數量。
- 歷史頁繼續呼叫 `window.RailAgentSupervisorHistory.snapshot()`。
- RailAgent 與設施回報的本機新增紀錄計數規則不變。
- 收到 `railagent:analytics-updated` 時，若底部「歷史」頁正在顯示，重新整理四個歷史區塊。
- 每次 React 導覽重繪後，先恢復 enhancer 曾隱藏的 React 節點，再依目前底部頁面重新套用正確版面，避免頁面混顯。

## 版面與文字

- 首頁主標題固定為「即時營運監控」。
- 底部導覽固定為「首頁／歷史／帳戶」。
- 歷史頁保留四個既有繁體中文標題與目前卡片樣式。
- 390px 手機寬度不得產生橫向捲動。
- 底部導覽選取狀態必須與實際顯示頁面一致。

## 驗收條件

1. 主管登入後預設進入首頁，看到「即時營運監控」。
2. 首頁沒有「跨運具服務事件中樞」與上方雙分頁按鈕。
3. 首頁只顯示已核准的即時營運內容。
4. 底部中間按鈕顯示「歷史」，不再顯示「待辦」。
5. 點擊「歷史」後顯示精確四個歷史分析區塊。
6. 歷史頁沒有原待辦內容、即時 KPI、站務人力或舊 Demo 卡片。
7. 點擊「帳戶」後維持原本主管帳戶頁。
8. 首頁與歷史來回切換三次，畫面不空白、不混顯、不重複產生卡片。
9. 歷史資料載入失敗時仍有四卡降級畫面。
10. 390px 手機寬度沒有橫向溢出。

## 不在本次範圍

- 不修改旅客或站務人員的底部導覽。
- 不改變歷史統計的資料來源、種子數字或計數規則。
- 不新增主管待辦功能的替代版本。
- 不修改主管帳戶頁內容。
