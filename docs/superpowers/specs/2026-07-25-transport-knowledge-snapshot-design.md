# RailAgent 運輸知識庫快照設計

## 目標

建立一套可重複執行的本機資料下載與轉換流程，將公開運輸資料保存於 `local-api/data`，並生成供 Ollama 檢索使用的知識文件。資料支援 RailAgent 的友善轉乘協助與一般問答；回答可追溯至原始來源與下載時間。

## 範圍與資料來源

| 範圍 | 資料 | 主要用途 |
| --- | --- | --- |
| 臺北捷運 OD | 臺北市資料大平臺的分時進出量 CSV 與資源清單 | 尖離峰與人流背景 |
| TDX 軌道 | 臺鐵、高鐵與臺北捷運的車站、路線、轉乘、定期時刻表資料 | 車站定位、跨運具轉乘、班表背景 |
| 臺鐵官網 | 車站、旅客服務、遺失物、無障礙及轉乘公開頁面 | 現場服務與無障礙指引 |
| 高鐵官網 | 車站、旅客服務、無障礙及轉乘公開頁面 | 高鐵站內與轉乘指引 |
| 臺北捷運官網 | 車站、營運、無障礙及旅客服務公開頁面 | 捷運站內與無障礙指引 |

只擷取與車站、路線、轉乘、無障礙、旅客服務及遺失物直接相關的公開內容；不進行全站爬取，也不下載須登入或受存取限制的內容。

## 檔案配置

```text
local-api/data/
  transport-raw/
    taipei-metro-od/
    tdx/
    tra-official/
    thsr-official/
    trtc-official/
  transport-knowledge/
    station-documents.jsonl
    transfer-documents.jsonl
    accessibility-documents.jsonl
    timetable-documents.jsonl
  transport-catalog.json
```

所有原始檔保留其來源格式；`transport-catalog.json` 是每次下載的目錄，至少記錄來源名稱、原始 URL、抓取時間、檔案路徑、格式、狀態與錯誤訊息。知識檔的每筆文件都含 `sourceUrl`、`downloadedAt` 與來源識別。

## 下載與轉換流程

1. 下載臺北市資料大平臺的 OD 資源清單及其公開 CSV。
2. 使用 TDX v3 基礎服務下載臺鐵、高鐵、臺北捷運的靜態資料與定期時刻表。下載器從 `TDX_CLIENT_ID` 和 `TDX_CLIENT_SECRET` 取得金鑰，絕不把憑證寫入原始碼、資料檔或 Git。
3. 下載三個官方網站已列入來源清單的公開服務頁面，保存原始 HTML 或官方原始檔，並擷取正文文字。
4. 將資料轉換成以車站、路線、轉乘、無障礙與班表為主題的 JSONL 文件；避免將完整逐班時刻表重複展開成大量相同內容。
5. 寫入更新後的資料目錄。任何失敗來源都保留在目錄中，不阻斷其他來源的下載。

## 資料品質與安全

- 每個知識文件均可回溯到原始檔與來源 URL。
- 時刻表標記為資料快照，不作為即時班次保證；回答需要提示使用者以官方即時資訊為準。
- 內容保留官方來源、下載日期與資料新鮮度，避免把舊資料表述成即時狀態。
- TDX 缺少憑證或回應受限時，目錄列出 `blocked` 狀態與補救方式；公開來源仍完成下載。
- 官方網站資料只用於本機檢索，不改寫或冒充官方即時服務。

## 驗證標準

- 下載器的單元測試覆蓋來源目錄、資料目錄、金鑰缺失和單一來源失敗不中止其他來源。
- 測試使用模擬 HTTP 回應，不對官方網站或 TDX 進行測試流量。
- 實際執行後檢查每個成功來源的檔案存在、目錄可解析，且知識文件都具有來源 URL 與下載時間。
- TDX 若沒有金鑰，驗證其被清楚標記而非偽造成功資料。
