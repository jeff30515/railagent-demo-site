# 九語系旅客功能一致性設計

## 目標

讓繁體中文、閩南語、客語、英文、日文、韓文、越南文、印尼文與泰文的「我是旅客」畫面使用同一套功能與互動流程；使用者僅會看見所選語言的文字。

## 約束

- 不使用即時翻譯、外部翻譯服務或需由使用者下載的語言包。
- 所有翻譯隨靜態網站部署，離線切換語言時仍可運作。
- 不改變既有案件追蹤、失物招領、友善轉乘、設施通報、會員登入／加入與返回身分選擇的功能行為或資料格式。
- 不新增第三方相依套件。
- 以 Unicode 文字與 CSS 字型備援顯示內容；缺少特定語音資產時，語音為可選增強功能，絕不阻斷介面或流程。

## 架構

新增一個隨站點載入的旅客語系協調器。它以目前被選取的九語言選項為唯一語系來源，包含完整靜態翻譯字典、純文字節點與可存取名稱的轉換規則，並監看 React 畫面與既有增強腳本產生的動態內容。

協調器只變更可見文案、placeholder、ARIA 名稱、標題與 HTML `lang`；按鈕、表單欄位名稱、事件處理器、網址 hash、本機儲存鍵與 API 呼叫一律不變。因此各語言會執行同一份功能程式，而不是維護九份頁面。

會員登入與案件取消這兩個現有的後載入增強腳本，會改用協調器公開的翻譯 API 建立內容，避免它們在語言切換或 DOM 重繪後重新插入繁中文字串。

## 資料流

1. 使用者點選語言選項。
2. 協調器辨識目前語系，更新 `document.documentElement.lang` 和旅客頁面的文字／可存取名稱。
3. React 或增強腳本新增、重繪旅客內容時，MutationObserver 重新套用同一語系。
4. 功能按鈕仍呼叫既有事件處理器和資料層；回饋、狀態與動態生成文字改由翻譯 API 產生。

## 失敗處理

- 找不到選取語言或翻譯鍵時，使用繁中作為安全後備，畫面與功能不會空白或失效。
- 儲存空間、語音或瀏覽器語音 API 不可用時，現有功能繼續運作，僅略過該可選增強。
- 翻譯規則僅作用於旅客頁面和明確列入字典的可見字串，不會修改事件 ID、使用者輸入、站名、API 資料或本機儲存內容。

## 驗收與測試

- 單元測試驗證九語系都有完整的必要旅客字典鍵，且未知語系會回退繁中。
- 單元測試驗證切換語言會保留表單欄位 ID、按鈕事件與案件取消行為。
- 靜態檢查驗證首頁載入協調器，現有增強腳本不再硬編碼旅客可見繁中文字串。
- 瀏覽器驗證逐一切換九語言，確認旅客首頁、會員、案件追蹤與回到身分選擇流程均可操作，且不需要網路翻譯服務。
