# RailAgent Demo｜競賽資料庫使用回饋與功能使用說明

> 更新日期：2026-07-27
> 說明對象：競賽主辦方與評審。

## 1. 資料使用概述

本作品下載並使用下列四項競賽資料庫（資料集）作為 RailAgent 的運輸知識來源。資料先保留來源網址與下載時間，再轉換為本機可檢索的知識快照；使用者提問時由 RailAgent 依車站、服務、轉乘或遺失物情境擷取相關資訊回答。

| 編號 | 資料提供機關 | 資料庫／資料集名稱 | 本作品用途 |
| --- | --- | --- | --- |
| 1 | 臺北市政府資訊局／臺北捷運公司 | 臺北捷運各站分時進出量統計 | 作為站點需求、尖離峰與旅運熱點的背景資訊。 |
| 2 | 臺灣鐵路公司 | 臺鐵官方旅客服務－車站無障礙服務 | 回答車站無障礙、協助服務與友善轉乘相關問題。 |
| 3 | 台灣高鐵公司 | 高鐵官方旅客服務－車站服務與無障礙服務 | 回答高鐵站內旅客服務與跨運具轉乘情境。 |
| 4 | 臺北大眾捷運股份有限公司 | 臺北捷運官方遺失物服務資訊 | 引導旅客正確處理臺北捷運遺失物、聯絡窗口與認領流程。 |

四項資料皆為下載後的快照資料，不是即時串接。其原始檔案格式包含 CSV 與官方網頁 HTML，並保留於本機的 `local-api/data/transport-raw/`，供後續更新與追溯來源。

## 2. 提供競賽方的四項資料庫使用回饋

### 整體回饋

這四項資料讓作品能跨臺北捷運、臺鐵與高鐵提供一致的旅客服務入口；官方來源可信，也適合用於 AI 回答時附上服務脈絡。實作上最需要改善的地方是資料格式與更新機制：目前有三項以官方網頁 HTML 提供，適合人工閱讀，但需要額外解析、清理與版本追蹤，較不利於穩定的系統介接與即時更新。

| 資料庫／資料集 | 實際使用回饋 | 對競賽資料平台的建議 |
| --- | --- | --- |
| 臺北捷運各站分時進出量統計 | CSV 格式容易匯入，可用來呈現站點旅運熱點、尖離峰差異與服務資源配置背景。 | 建議明確提供欄位定義、站碼對照、資料涵蓋期間與更新頻率；若可提供固定 API 或增量更新檔，能更容易做長期趨勢分析。 |
| 臺鐵官方車站無障礙服務 | 官方資訊可支援無障礙導引與友善轉乘說明；但 HTML 頁面結構若調整，解析程式就需要跟著修改。 | 建議同步提供 JSON、CSV 或 API，並將車站、設施類型、服務說明、可用狀態、更新時間拆成結構化欄位。 |
| 高鐵官方車站旅客服務與無障礙服務 | 有助於回答高鐵站內服務及跨運具轉乘問題，能補足多運具服務場景。 | 建議提供可機讀的車站服務清單，包含服務類別、適用車站、服務時間、聯絡方式與最後更新時間，方便系統直接檢索。 |
| 臺北捷運官方遺失物服務資訊 | 可正確引導旅客處理遺失物與認領流程，適合作為客服問答知識。現階段是「流程資訊」，不是可搜尋的遺失物明細資料庫。 | 若可提供去識別化的遺失物公開資料或 API，例如物品類別、拾獲站點、拾獲日期、保管狀態與案件識別碼，將能支援更精準的自動比對與追蹤服務。 |

### 導入時遇到的共通限制

1. 官方網頁內容以人閱讀為主，標題、段落與表格結構可能變更；需建立定期重新下載與格式檢查機制。
2. 資料下載後需轉為可檢索快照，因此新公告或服務異動不會立即反映，必須重新整理資料集。
3. 對遺失物情境而言，服務流程頁可回答「應如何處理」，但無法直接回答「是否已拾獲某一個物品」；後者仍需要可查詢的遺失物明細與狀態資料。
4. 若未來提供統一的跨運具資料欄位與更新時間欄位，可顯著降低整合成本，也能提升 AI 回答的可追溯性。

## 3. 各功能使用說明

### 3.1 身分選擇與語言

1. 開啟公開網站後，選擇「我是旅客」或「站務／主管」。
2. 旅客入口可切換繁中、臺語、客語、英文、日文、韓文、越南文、印尼文與泰文。
3. 各角色可使用「切換身分／返回身分選擇」回到角色入口。

### 3.2 視障使用者操作說明

RailAgent 的導讀模式在網站載入後即啟用，語音是輔助，不取代畫面上的文字與表單標籤。

1. **進入與選擇身分：** 使用螢幕閱讀器或鍵盤 `Tab` 在語言按鈕、旅客與站務／主管身分卡之間移動；焦點移到可操作項目時，系統會讀出該項名稱。按 `Enter` 或 `Space` 選取。
2. **頁面導讀：** 在旅客首頁，以滑鼠滑過、鍵盤聚焦或點擊「切換身分」、服務卡、主要按鈕與底部導覽列時，系統會播放對應導讀。導讀優先使用網站內建語音檔，無法播放時才使用瀏覽器的語音合成。
3. **填寫遺失物表單：** 按 `Tab` 依序移到各欄位；焦點進入欄位時會讀出欄位名稱、提示與填寫說明。輸入完畢後，將焦點移到「搜尋可能相符物品」並按 `Enter` 或 `Space` 送出。
4. **閱讀搜尋結果與追蹤：** 搜尋結果區有即時通知標示；螢幕閱讀器會讀出候選結果。以 `Tab` 移到候選物的「追蹤」按鈕後按 `Enter` 或 `Space`。完成後到下方「案件」頁，以同樣方式確認或取消追蹤。
5. **使用 RailAgent：** 開啟對話框後，焦點會移到問題輸入框；輸入問題並送出。對話訊息區設為即時通知，回答出現時可由螢幕閱讀器讀出。
6. **使用友善轉乘：** 開啟工具後，焦點會移到站名輸入框。可直接鍵入站名，或使用「開始語音輸入」說出站名；查詢成功後，系統會讀出站點確認與電話資訊，並提供可直接撥打的連結。

> 若瀏覽器沒有聲音、未安裝適合語言的語音，或不使用語音導讀，仍可完全以螢幕閱讀器加鍵盤操作；所有主要控制項均保留可讀取的文字與 ARIA 標示。

### 3.3 聽障使用者操作說明

1. **全程以文字完成操作：** 身分、服務卡、表單欄位、送出按鈕、搜尋結果與任務狀態皆以文字顯示；不需要依賴網站語音才能完成流程。
2. **查看系統回應：** 遺失物候選結果、RailAgent 回答、站點確認、錯誤訊息與追蹤結果都會直接顯示在畫面上。語音導讀只是同步提示，並不承載唯一資訊。
3. **友善轉乘的文字流程：** 在站名欄位直接輸入所在站名，再按「查詢／確認」即可。若使用語音輸入，辨識結果會回填並顯示在文字欄位；辨識失敗或瀏覽器不支援時，畫面會顯示原因，仍可改用手動輸入。
4. **聯絡站務：** 查詢結果會顯示站務電話文字與可撥號連結；如不便以電話聯絡，可將電話號碼、站名與問題文字提供給同行者或站務服務台。
5. **回饋與案件確認：** 在「案件」頁可直接讀取追蹤狀態，並以文字填寫滿意度與意見後送出。

> 目前作品以「文字優先、語音輔助」設計，尚未提供手語翻譯視訊或即時文字轉譯通話；需要這兩項服務時，仍應由現場站務人員或既有通訊輔具協助。

### 3.4 旅客：遺失物搜尋與追蹤

1. 在首頁遺失物表單輸入品項與可辨識特徵；可補充遺失日期、可能遺失站點、車次、顏色與品牌。
2. 按「搜尋可能相符物品」後，系統會依品項、特徵、站點、車次、日期、顏色與品牌進行候選排序。
3. 對候選物按「追蹤」後，可在底部「案件」頁確認；需要停止時按「取消追蹤」。
4. 追蹤案件會同步成對應站點可見的任務，供站務與主管確認。

### 3.5 旅客：RailAgent 問答與友善轉乘

1. 在 RailAgent 對話框輸入車站、服務、無障礙或轉乘問題後送出。
2. 系統從四項下載資料所建的運輸知識快照中檢索相關內容，再產生回覆。
3. 需聯絡站務時，開啟友善轉乘／站務協助工具，輸入所在車站；支援的瀏覽器可使用語音輸入。
4. 系統顯示站點確認資訊與可撥打的站務電話連結，旅客可依引導完成後續聯絡。

### 3.6 旅客：設施回報與服務回饋

1. 在設施回報區填寫問題位置與情況後送出。
2. 服務處理完成後，到「案件」頁的「服務回饋」填寫滿意度 1–5 分與文字意見，再按「送出回饋」。

### 3.7 站務：最新任務、完整任務與拾得物登錄

1. 站務首頁的「最新任務」最多顯示 3 筆最新遺失物追蹤案件。
2. 按底部「任務」可查看該單位可見的完整任務清單。
3. 到「登記拾得物」頁填寫物品類型、顏色、品牌、特徵、拾得地點、拾得日期與列車資訊後送出。

### 3.8 主管：即時監看與歷史服務品質

1. 主管首頁可查看目前旅客追蹤數、任務與服務概況。
2. 旅客新增或取消追蹤後，主管端的追蹤數與任務會隨同步結果更新。
3. 前往「歷史服務品質」可查看服務品質、使用次數與回饋趨勢。
4. 帳戶頁顯示主管所屬單位與帳號，並可返回身分選擇。
